# Durable local runner contract v1

Scope: a sequential, native Linux Go CLI, local files and explicitly selected trusted local executables. No model qualification, network service, shard protocol, grader or statistical inference.

## Frozen JSON and operations

All JSON is UTF-8, rejects unknown/duplicate keys and trailing values, uses standard padded base64, lowercase 64-hex SHA-256 and integer budgets. Identity hashes use compact Go encoding/json encoding of the typed structures (field order in benchmark/types.go), without a trailing newline. Arrays retain order. No implicit budgets.

Plan v1 fields: version=1, profile={protocol:"local-request-v1",sha256}, models={B,P} digests, adapter_sha256, adapter_args_sha256 (hash of compact JSON string array; empty argv is []), items=[{id,input_base64,input_sha256}], draws=[{id,seed}], requests=[{item,arm,draw,seed,model_sha256,input_sha256,profile_sha256}], failure_policy="record_all"|"require_stop", timeout_ms (1..3600000), max_output_bytes (256..1048576), max_tokens (1..1000000). Identifiers are 1..64 ASCII letters/digits/underscore/hyphen. Items/draws are nonempty unique sets; requests must equal their full B/P cross product exactly, including matching seeds and digests. Maximum plan size 8 MiB, 10000 requests. Profile compatibility requires the fixed protocol and echoed exact profile digest. The slice binds model/profile digests, but cannot attest that an adapter actually loads them.

CLI: `bench validate --plan FILE`; `bench run --plan FILE --journal FILE --adapter /absolute/executable -- [ARGV...]`; `bench status --plan FILE --journal FILE`; `bench final --plan FILE --journal FILE --out NEWFILE`. Executable files must be regular, single-link, non-symlink, at most 64 MiB, and immutable throughout the run. Run creates a new journal exclusively or replays an existing one, checks adapter bytes/argv against the frozen plan and processes requests in declared order. The plan contains no executable path or executable command text. Status only emits INCOMPLETE progress counts, even when all requests are present; final alone emits COMPLETE after the exact gate. Final exports sealed request outcomes with quality UNKNOWN, never quality numbers. Existing final outputs are refused, never overwritten. Final validates the whole candidate before any output file is created.

## Local adapter v1

One process per attempt. Stdin: one JSON envelope `{version:1,plan_sha256,request_id,attempt_id,request,input_base64,max_tokens}`. Request ID hashes `{plan_sha256,request}`; attempt ID is 32 lowercase random hex characters, independent of request identity. Stdout: exactly one JSON receipt `{version:1,plan_sha256,request_id,attempt_id,request,completion_base64,completion_sha256,tokens,finish,failure}`. All binding fields must exactly echo stdin. Completion digest covers decoded bytes; tokens is 0..max_tokens. Adapter finish: stop/truncation/error/resource_stop. Stop requires empty failure; other finishes require a nonempty bounded failure label. Runner-only finishes: timeout/adapter_error. Each stream is bounded by max_output_bytes; stdout/stderr overflow or nonzero exit produces runner adapter_error with empty completion, zero tokens and a fixed label. Here zero tokens means no retained token evidence, not zero underlying adapter work. Stderr is bounded and never retained. Malformed output, mismatched identities, unsafe contents or incorrect hashes cause refusal with the start retained as uncertain, never an accepted receipt. Deadline produces timeout. Runner cancellation leaves an unmatched start; it never accepts a completion. Child processes are unsupported: adapters must finish and close their own I/O, must not spawn descendants. Only the direct PID is killed. Environment is fixed PATH/LANG/TZ, no inherited secrets. This is a trusted executable interface, not an OS sandbox. No automatic model inference is performed by the runner itself.

## Journal and recovery

Local filesystem only. Existing parent directory must be trusted, private and not concurrently renamed/replaced. A persistent sibling `.lock` file is locked with nonblocking Linux flock for every operation, including readers; crashes release the lock. Do not delete/replace lock files. Files must be regular, single-link, non-symlink files. No distributed/NFS ownership claim. Journal is never overwritten/truncated/repaired automatically.

New journal: exclusive create, file sync and directory sync, followed by a synced header. A record is one JSON line `{seq,prev_sha256,event,sha256}`; sha256 hashes compact JSON `{seq,prev_sha256,event}`. Events are header (plan_sha256), start (full envelope), receipt (full receipt). Hash chain starts with 64 zeros. Only an exact known start can receive one receipt. Attempts and request IDs remain separate. At most one accepted receipt per exact request; duplicates, conflicts, wrong hashes/identities, impossible event ordering and changed plans are refused before further writes. Append acknowledgement follows Write + file Sync. Any write/sync failure stops the operation; replay is required. An empty journal (including a crash before header), a truncated final line or any corrupt record causes strict refusal, preserving all original bytes. Recovery outside this contract requires retaining the original and an independently audited new journal; no repair flag is supplied.

A durable unmatched start is uncertain/incomplete. On resume a new attempt may run for the same request; the original attempt is retained. An adapter side effect followed by a crash can therefore run twice. No globally exactly-once claim. A durable accepted receipt is reused, even if the previous process crashed before acknowledging it. Record_all accepts all validated terminal outcomes, including failures; require_stop records failed attempts but stops and leaves their requests incomplete for a later retry. Failure counts remain visible and final denominators include all required outcomes. Resource-stop/truncation/timeout/error never become graded answers: quality remains UNKNOWN for every outcome.

Fault injection is compiled only into Go tests/test CLI entry points using internal callbacks, never controlled by production environment variables or flags. Tests terminate real CLI fixture processes at start/receipt write/sync/ack boundaries. A fully written line that survived a crash may be replayed after revalidation and a file sync; no half line is accepted. Storage/power-loss correctness relies on OS/filesystem honoring Sync; no hardware power-loss qualification is claimed.

## Export custody and gate

Final requires every exact required request to have its policy-accepted terminal receipt, valid complete chain, pairing and byte hashes. Missing/conflicting/foreign evidence produces an error, no final stdout and no final file. Export is compact JSON `{version:1,state:"COMPLETE",plan_sha256,journal_sha256,quality:"UNKNOWN",outcomes:[...] ,sha256}` with sha256 over those fields excluding sha256. Outcomes are ordered by frozen requests. A synced private temporary file is linked to the new output path without replacement, then its directory is synced. A directory-sync error can leave a complete final file with uncertain durability. A crash can leave a complete temporary file or complete final file, never a partial final path. Existing output can be independently checked by hash; retry must use a new path. No multi-file final transaction.

Plans, adapter arguments, decoded inputs/completions and exports reject recognized token-shaped strings and nonempty secret-named JSON fields. This bounded detection is not a general secret classifier; operators must supply only nonsensitive data. Rejection errors never echo offending contents.
