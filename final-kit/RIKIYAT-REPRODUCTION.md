## Extraction, strict/lenient scoring and cuts

`mathqa.answer_text` drops text through the last `</think>` when present, otherwise reads the whole reply. `last_boxed` chooses the **last `\boxed` occurrence**, falling back to the last `\fbox` only when no boxed occurrence exists. It balances nested braces, permits whitespace before a brace and the special space-form `\boxed 5` up to `$` or newline. Empty/unclosed last boxes return None; it does not search backward for an earlier valid box. Extracted and gold strings are each parsed by math-verify after wrapping in a box; missing/unparseable values and verify exceptions are false. Parsing/verification timeout is five seconds on the main thread (disabled off-thread). Exact math-verify version for the original logs is not pinned; the HF rerun separately names 0.9.0.

Primary `acc` is the fraction of correct sampled answers. **No cap-hit-wrong override exists.** A correct extracted box may score correct even when finish_reason is length. Secondary `acc_lenient` adds an unboxed-answer recovery only if strict grading failed **and no boxed prediction exists**: latest numeric/formula-bearing Final Answer / the answer is / Answer phrase, else last number; try the extracted phrase or its last number with math-verify. A wrong box is not rescued by lenient fallback. Where source merged data says null, lenient evidence is unavailable, not zero and not equal to strict by assumption.

Multiple choice calls an unavailable `mcqa.extract`; evaluate.py compares the extracted letter to gold. Its docstring says extraction follows the official MMLU reading after the last thinking close; that is insufficient to claim exact regex equivalence. IFEval reads after the last `</think>`; thinking-on with no closing tag yields an empty answer. Each non-null instruction kwarg builds the official instruction; prompt-dependent checks receive the original prompt. **All** checks must pass for strict prompt-level accuracy. Instruction-level counts are secondary; there is no IFEval loose metric implementation in this code. Non-math `ok_lenient` just accumulates the same correctness, not a new lenient checker.

`cut_share = count(sample.finish_reason == "length") / total sampled answers`; `mean_tokens` uses vLLM output `token_ids` lengths including generated thinking. Cap hits, unfinished no-answer outputs and accuracy remain distinct quantities. Per-problem files retain correctness per sample and first prediction; first-sample text dumps do not establish every sample's finish reason. Published aggregate cut counts can be arithmetically checked, but cannot be independently reclassified from absent per-sample termination evidence.
